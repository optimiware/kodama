# Workspaces: what the memory adapters do not model

`MemStore` (`workspace.Store`) runs `StoreContract` over `memdb`, and `LocalGit` (`LocalReader` for `workspace.RefReader`, `LocalPreparer` for `workspace.SourcePreparer`, `LocalPublisher` for `workspace.RefPublisher`) runs `GitContract` over temporary bare repositories driven by the Git executable (SD-13). `NewLocalGit()` (an owned temporary root) or `NewLocalGitAt(root)` builds it without `testing.TB`; `Close` removes an owned root; `LocalGitFor(t)` is the test wrapper. `MemStore`, `LocalGit` and each of its three ports (`g.Reader()`, `g.Preparer()`, `g.Publisher()`) are flagged development-only (`DevelopmentOnly() bool`; SD-12). `MemServiceEnv` wires the real `workspace.Service` over `MemStore` and `LocalGit`, so the actual bundle upload, verification, staging and publication run without a database or a server. `MemStore.UpdateInTx` takes the caller's `memdb.Tx` as `postgres.UpdateInTx` takes its `pgx.Tx`, so work admission, secret pins and event appends join one unit.

Deliberately not modeled:

- **Locks.** There is no workspace row lock and no lock order. A mutation runs on a private copy and is committed by one `Update`; serialized writers make the version comparison trivially true. Concurrent reservations, publisher claims and fences are PostgreSQL obligations (T-026), not memory ones.
- **Schema constraints.** The foreign key to the project, the later foreign keys to attempts and artifacts, RLS and column types are SQL. Memory keeps uniqueness of the work item, the work branch and a retained reference name per workspace.
- **Audit detail.** Audit entries keep the action, actor, reason and request ID; their metadata map and `occurred_at` are not stored, and the contract reads only the sorted actions.
- **Source preparation limits.** `LocalPreparer` checks the bundle header, digest, size, prerequisites, ancestry and the secret needles, and stages the commit from a scratch repository. The import runs with `fetch.fsckObjects`/`transfer.fsckObjects` so a correctly hashed but invalid object is refused as corrupt. The expanded size of the introduced objects is summed from `cat-file --batch-check` and bounded (`SetMaxExpandedBytes`, default 256 MiB) before any content is read, the secret scan streams through a bounded window and its process is stopped on refusal, and fetches run under a polled scratch bound (`SetMaxScratchBytes`, default 256 MiB) that includes the bundle itself; every refusal removes its scratch. There is no per-command deadline beyond the caller's context and no process sandbox, and the scratch bound is polled (10 ms), so a fast writer can overshoot it briefly before the command is killed. The malformed-object contract case (`GitEnv.CorruptObject`, `ScratchLeft`) runs for both the local and the HTTPS preparer; the expanded-size and scratch-bound cases (`GitEnv.Bounds`) run for the local Git only, because the HTTPS adapter exposes no expanded-size bound and its scratch bound is covered by its own tests. A prepared source is accepted only by the publisher of the same `LocalGit`.
- **Credentials and transport.** The local Git has no tokens, TLS or smart HTTP; the repository is addressed by a path directly under the adapter's root and refuses any other. Credential separation between the reader and the publisher is by type (the reader has no write method), not by secret.
- **Atomic ref races.** The expected-old-ref update is Git's own compare-and-swap on the file system; dropped acknowledgments and server-side holds (`gitfx` faults) cannot be injected.
- **Restart persistence.** The store vanishes with the process; the bare repositories vanish with the test's temporary directory.
- **Create-only collisions.** `MemStore.Insert` refuses a reused workspace ID, work branch or work item (`ErrConflict`); PostgreSQL's `ON CONFLICT DO NOTHING` reports the ID collision differently, so the contract asserts only that it fails and changes nothing.
