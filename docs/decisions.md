## Internal Git service — 2026-10-30 (O-31)

**Resolved direction by the owner on 2026-10-30.** Kodama is a full-cycle SDLC in a dedicated Kubernetes installation, inspired by Drone CI's simplicity: tasks, issues or change requests go in; deployed code comes out. It embeds its own Git service (like a GitHub/GitLab) and its own issue tracker (like a Jira/Kanban board). Because agents do most of the source work, Git is mostly automated rather than exposed; engineers can still fetch a project or branch to debug, review or fix it, and can push an existing project into Kodama.

| Area | Selection |
| --- | --- |
| Hosting | Repositories are project resources hosted by Kodama; metadata in PostgreSQL, history in Git |
| Implementation | Native Git binaries (`git http-backend`, receive/upload-pack, hooks, maintenance) wrapped by Go for authentication, authorization, provisioning and event integration |
| Isolation | Tenant isolation from the first release; P-17 selects one worker and one volume per tenant as the baseline |
| Events | Accepted pushes become durable events that start pipelines: push → verify and deploy, integration → review, revert → explicit pipeline |
| Coordination | Git joins support services (databases, Valkey) as coordination layers for agents, with project lifetime instead of run lifetime |

This amends O-03, C-12/P-06/P-07 for internally hosted repositories (agents push their own branches with scoped grants; the publisher remains for external repositories) and ADRs 0004/0005. It does not change the run models of ADR 0010, the event bus (C-11) or the human gate and completion rules (C-13). Open follow-ups are O-32 and O-33.
